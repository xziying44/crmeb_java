# 业务员系统设计方案

> 生成时间: 2026-01-21
> 项目版本: CRMEB Java v1.4
> 设计目的: 简化分销架构，业务员直接管理散客

---

## 一、需求背景

### 1.1 核心变更

**原架构（需求文档）：**
```
管理员 → 业务员 → 一级经销商 → 散客
```

**新架构（简化版）：**
```
管理员 → 业务员 → 散客（直接绑定）
```

### 1.2 变更原因

- 暂时不需要一级分销商角色
- 业务员直接承担原一级分销商的职能
- 主要目的是统计业绩信息，返点通过线下结算

---

## 二、系统架构

### 2.1 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                      客户端层                            │
├─────────────┬─────────────┬─────────────────────────────┤
│  admin      │  salesman   │  app                        │
│  管理后台    │  业务员端    │  商城小程序                  │
│  (Vue+EUI)  │  (新增-移动) │  (uni-app)                  │
│  :8080      │  复用admin接口│  :8081                     │
└─────────────┴─────────────┴─────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────┐
│                    API 服务层                            │
│                  crmeb-admin (:8080)                    │
│              新增业务员相关接口                           │
└─────────────────────────────────────────────────────────┘
```

### 2.2 业务员端技术选型

| 项目 | 选型 | 说明 |
|-----|------|-----|
| 框架 | uni-app | 与现有 app 保持一致，支持小程序/H5/APP |
| 接口 | crmeb-admin API | 复用认证机制，新增业务员专属接口 |
| 认证 | JWT | 复用 admin 的 JWT 认证 |

### 2.3 业务员账号体系

- **复用 SystemAdmin 表**：业务员是特殊角色的管理员
- **通过角色区分**：`eb_system_role.is_salesman_role` 标识业务员角色
- **扩展信息分离**：独立的 `eb_salesman_info` 表存储邀请码、二维码等

## 三、数据模型设计

### 3.1 表结构调整

#### eb_system_role 新增字段

```sql
ALTER TABLE eb_system_role ADD COLUMN (
  is_salesman_role TINYINT(1) DEFAULT 0 COMMENT '是否业务员角色 0-否 1-是'
);
```

#### eb_salesman_info 新增表

```sql
CREATE TABLE eb_salesman_info (
  id              INT(11) PRIMARY KEY AUTO_INCREMENT,
  admin_id        INT(11) NOT NULL COMMENT '关联的管理员ID',
  salesman_code   VARCHAR(32) NOT NULL COMMENT '业务员邀请码（唯一）',
  salesman_qrcode VARCHAR(255) NULL COMMENT '业务员二维码图片地址',
  bindable        TINYINT(1) DEFAULT 1 COMMENT '是否可被绑定 0-否 1-是',
  create_time     DATETIME DEFAULT CURRENT_TIMESTAMP,
  update_time     DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_admin_id (admin_id),
  UNIQUE KEY uk_salesman_code (salesman_code)
) COMMENT '业务员扩展信息表';
```

#### eb_user 新增字段

```sql
ALTER TABLE eb_user ADD COLUMN (
  salesman_id        INT(11) DEFAULT 0 COMMENT '绑定的业务员ID（admin_id）',
  salesman_bind_time DATETIME NULL COMMENT '绑定业务员时间'
);
```

### 3.2 设计说明

| 设计点 | 说明 |
|-------|------|
| 角色驱动 | 通过 `eb_system_role.is_salesman_role` 判断是否业务员角色 |
| 信息分离 | 业务员专属信息独立存表，保持 `eb_system_admin` 表干净 |
| 一对一关系 | `eb_salesman_info.admin_id` 唯一，确保一个管理员只有一条业务员信息 |
| 邀请码唯一 | 用于用户注册时输入绑定 |
| 二维码存储 | 生成后存储图片地址，避免重复生成 |

## 四、功能模块设计

```
业务员管理

│   ├── 查看所有业务员

├── 业务员业绩统计
│   ├── 各业务员客户数量

│   └── 业务员业绩排行榜

    ├── 查看所有散户绑定关系
    └── 解绑/转移客户

│   └── 复用 admin JWT 认证

│   ├── 客户列表（搜索/筛选/排序）
│   ├── 客户详情（基本信息/订单记录/消费统计）

│   └── 客户分组

    ├── 个人信息
    └── 修改密码
```

### 4.3 散户绑定方式

## 六、关键业务流程

### 6.1 业务员创建流程

```
管理员操作 (Admin后台)
    │
    ▼
┌─────────────────────────────┐
│ 1. 进入「业务员管理」菜单     │
│ 2. 点击「添加业务员」         │
│ 3. 填写：姓名/手机号/密码     │
│ 4. 系统自动：                │
│    - 创建 admin 账号         │
│    - 分配业务员角色           │
│    - 生成唯一邀请码           │
│    - 生成专属二维码           │
└─────────────────────────────┘
```

### 6.2 散户绑定业务员流程

**方式A：注册时输入邀请码**
```
用户 (小程序)                         系统
    │                                  │
    ├─ 打开注册页面 ──────────────────►│
    │                                  │
    ├─ 输入手机号+验证码+邀请码 ──────►│
    │                                  │
    │◄─────────────────── 校验邀请码 ──┤
    │                                  │
    │◄─── 注册成功，自动绑定业务员 ────┤
```

**方式B：扫码绑定**
```
用户 (小程序)                         系统
    │                                  │
    ├─ 扫描业务员二维码 ──────────────►│
    │                                  │
    │◄──────────── 跳转小程序绑定页 ───┤
    │                                  │
    ├─ 未登录 → 先注册/登录 ─────────►│
    ├─ 已登录 → 确认绑定 ────────────►│
    │                                  │
    │◄─────────────── 绑定成功提示 ────┤
```

### 6.3 业务员添加客户流程

```
业务员 (业务员端)              系统                    客户
    │                          │                       │
    ├─ 输入客户手机号 ────────►│                       │
    │                          │                       │
    │                          ├─ 发送验证码 ─────────►│
    │                          │                       │
    │◄── 等待客户提供验证码 ───┤                       │
    │                          │                       │
    ├─ 输入验证码 ───────────►│                       │
    │                          │                       │
    │◄─── 创建成功，自动绑定 ──┤                       │
```

## 七、需求文档更新要点

### 7.1 角色需求对比（第 3.1 节）

| 原内容 | 修改为 |
|-------|-------|
| 一级经销商：可用分销员模式，但需要独立价格体系、返点机制 | **删除此行**，暂不需要一级经销商 |
| 业务员：需要新增业务员角色，能创建经销商账号 | 业务员：独立移动端系统，直接管理散客，统计业绩 |

### 7.2 功能需求对比（第 3.2 节）

| 原内容 | 修改为 |
|-------|-------|
| 业务员返点 | 暂不开发，线下结算 |
| 不同客户不同价格 | 暂不开发 |

### 7.3 业务员管理模块（第 4.2 节）

原内容移除「经销商创建」部分，改为：

```
业务员管理模块
├── 业务员账号（Admin后台管理）
│   ├── 管理员创建业务员账号
│   ├── 分配业务员角色
│   ├── 生成邀请码/二维码
│   └── 业务员启用/禁用
├── 客户管理（业务员端）
│   ├── 添加客户（短信验证码确认）
│   ├── 客户列表/详情
│   ├── 客户备注/标签/分组
│   └── 邀请码/二维码推广
└── 业绩统计
    ├── 客户数量统计
    ├── 订单金额统计
    ├── 客户活跃度
    ├── 客户消费排行榜
    └── 销售趋势图（日/周/月）
```

### 7.4 暂时移除的模块

以下模块标记为「暂不开发」：

- 经销商等级管理（第 4.3 节）
- 经销商价格体系（第 4.3 节）
- 返利与积分扩展中的业务员返点（第 4.5 节）
